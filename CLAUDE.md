# AmpersandOfTruth

48-hour Junction hackathon project. **Speed > polish, but `main` must always demo.**
Blazor Web App on .NET 10, **Interactive Server** render mode everywhere (no WASM, no separate API).
Persistence: **EF Core 10 + SQLite** (`src/AmpersandOfTruth.Web/app.db`, git-ignored, migrated automatically on startup) for app state.
Wikipedia corpus: **MariaDB 12.3 on the team VPS**, raw SQL via `MySqlConnector` (see *Corpus* below).
Query embeddings: **Ollama `bge-m3`** (local, else the VPS through the tunnel) behind `IQueryEmbedder` (see *Embedding* below).

## Conventions

- **One feature = one folder.** Parallel agents should only collide on `Program.cs` (one line) and `NavMenu.razor` (one block). Keep it that way.
- Namespaces follow folders (`AmpersandOfTruth.Web.Features.Notes`). File-scoped namespaces, primary constructors, records for data.
- Services: interface only if there are 2+ implementations or you need to fake an external API. Otherwise inject the concrete class.
- Singleton state is shared by **every user/circuit** → must be thread-safe. Per-user state → `AddScoped` (scope = one browser tab's circuit).
- When a service raises events consumed by components, update UI via `InvokeAsync(StateHasChanged)` and unsubscribe in `Dispose`.
- Inject `TimeProvider` instead of `DateTime.Now` (testable).
- UI: Bootstrap 5 classes are already loaded (`wwwroot/lib/bootstrap`). Don't add a component library unless the team decides to.
- **UI look and feel = `docs/design/`** (read its `README.md` first). It is Wikipedia-inspired and quiet: 2px corners, white page with grey infobox panels, no shadows, serif titles with a rule under them, system fonts, link blue as the only saturated colour. Styles come from `docs/design/tokens.css` + `aot.css` (copied into `wwwroot/app.css`). Match the component and page previews (`components/*/preview.html`, which open in a browser). Tier wording only via `TierBadge`. Change the design by editing those files in the same PR, never ad hoc in a page.
- Put `data-testid="..."` on elements tests interact with; tests select by it, not by CSS classes.
- **Evidence wording is decided, not improvised** (`docs/evidence-standard.md`, code in `Features/Evidence`): tier labels come from
  `EvidenceTiers`, levels from `TierRules`, editor names/IPs from `EditorDisplay` (IPs masked), license/methodology text from
  `Attribution`/`Methodology`. Never label an account (propagandist, troll, …) or claim certainty ("proven"); `CopyRules` tests scan every `.razor` file.
- Secrets (API keys): `dotnet user-secrets set "Key" "value" --project src/AmpersandOfTruth.Web`, read via `IConfiguration`. Never commit keys; never put them in `appsettings*.json`.

## Persistence (EF Core + SQLite)

- **Don't add `DbSet` properties to `AppDbContext`.** Add an `IEntityTypeConfiguration<T>` in the feature folder (auto-discovered) and query with `db.Set<T>()`.
- Services inject `IDbContextFactory<AppDbContext>` and create a context **per operation** (`await using var db = await dbFactory.CreateDbContextAsync()`). Never inject `AppDbContext` into components or keep one in a field — a Blazor circuit lives for the whole tab session and DbContext isn't thread-safe.
- Read queries: `.AsNoTracking()`. Bulk delete/update: `ExecuteDeleteAsync` / `ExecuteUpdateAsync`.
- Changed an entity or configuration → add a migration in the same commit. `verify.sh` fails if you forget.
- SQLite limits: `DateTimeOffset` is auto-stored as UTC ticks (a convention in `AppDbContext`) so it sorts — always use UTC. `decimal` can't be ORDER BY'd or SUM'd in SQL → use `double` or long cents for money/scores.
- **Parallel branches + migrations:** both branches edit `AppDbContextModelSnapshot.cs` → merge conflict. Fix: take `main`'s snapshot, delete *your* migration files, re-run `dotnet ef migrations add`. Never hand-merge the snapshot.
- Seed demo data inside a feature service, idempotently (check `AnyAsync()` first), not in migrations.

## Corpus (MariaDB on the VPS)

- Read-mostly shared DB `corpus` (articles, revisions, vectors) + scratch schema `research`. No EF, no migrations: raw SQL.
- Inject `CorpusConnectionFactory` (singleton, pooled) → `await using var c = await corpus.OpenAsync(ct);` per operation.
- Config: `ConnectionStrings:Corpus` (appsettings, defaults to the tunnel `127.0.0.1:3307`, user `corpus_ro`) +
  password in user-secrets: `dotnet user-secrets set "Corpus:Password" "<pw>" --project src/AmpersandOfTruth.Web` (ask a teammate; it's in `/opt/junction/corpus/.env` on the VPS).
- Users: `corpus_ro` = SELECT on `corpus`, full rights on `research` (app + experiments). `corpus_rw` = loaders/precompute only.
  **Experiments create tables in `research.*`, never in `corpus.*`.**
- Vector params: `cmd.Parameters.AddWithValue("@q", CorpusVectors.ToBytes(embedding))` (raw little-endian float32); `VEC_FromText(@json)` also works.
  `mhnsw_ef_search=80` is the server default — no per-session SET needed.
- **`verify.sh` must pass with the corpus absent.** Corpus tests use `[CorpusFact]` (skipped unless `CORPUS_TESTS=1`).
  The `corpus` health check reports `Degraded` (still HTTP 200) when the tunnel is down; startup never depends on it.
- Bulk jobs (loads, precompute) on 2 vCPUs starve interactive queries — run them early, never during a demo.
- `corpus-deploy.sh` rsyncs `deploy/corpus/` with `--delete`: anything that lives only in `/opt/junction/corpus` on the VPS
  (`loader/` + `data/` + `.venv/` + `.upstream-rag/` used by `scripts/corpus/load-*.sh --remote`) must be in its `--exclude` list
  or a deploy wipes it.

## Embedding (bge-m3 via Ollama)

- Topic search only works with vectors from **`bge-m3` (1024-d)** — the model that built the dataset. Never Gemini embeddings.
- Inject `IQueryEmbedder` → `float[] v = await embedder.EmbedAsync(topic, ct)`; pass to SQL with `CorpusVectors.ToBytes(v)`.
  It's cached (memory + SQLite `QueryEmbeddings`, keyed by model + whitespace-normalised text, case kept), so a demo topic
  embedded once works even with Ollama down. Catch `EmbeddingUnavailableException` → show a "search unavailable" state.
- Endpoints: `Embedding:OllamaUrl` (default `127.0.0.1:11434` = laptop Ollama, or the VPS's own when the app runs there), then
  `Embedding:FallbackOllamaUrl` (`127.0.0.1:11435` = VPS Ollama via `scripts/corpus-tunnel.sh`). Local is optional: `ollama pull bge-m3`.
- `OllamaQueryEmbedder` (concrete, uncached) only to bypass the cache. Tests: `FakeQueryEmbedder` (deterministic unit vectors, `Unavailable` switch).
- The VPS Ollama (2 vCPU) is for **one short query at a time**. Bulk embedding (P1.R5) runs on a laptop with a GPU/Apple silicon.
- Ollama ≤0.12.x aborts on any bge-m3 input over ~512 tokens (`GGML_ASSERT ... n_ubatch >= n_tokens`, HTTP 500 + model reload) —
  the VPS pins 0.40.16 (verified cosine 1.00000 vs stored vectors). Use a recent Ollama on laptops too.
- `embedding` health check reports `Degraded` when no endpoint has the model; startup never depends on it.

## Investigation pipeline (`Features/Investigations/Pipeline`, issue #39)

- `/investigate` consumes `IInvestigationRunner.RunAsync(topic, ct)` → `IAsyncEnumerable<InvestigationEvent>`:
  `ArticlesFound → RevisionsScanned → CandidateScored × N → Completed`, or a `StageFailed` that ends the run (never an exception;
  cancellation ends the stream with `OperationCanceledException`). The P2 fixture runner (#98) implements the same interface.
- Output = `IncidentRecord`, the C# twin of `research/eval/schemas/incident.schema.json` (serialise with `IncidentJson.Options`;
  `IncidentRecordTests` keeps record and schema in sync — change both together).
- Stages are interfaces, one per P1 experiment, swapped in `InvestigationsFeature` without touching the orchestrator or the UI:
  `ITopicSearch` (R6), `ICandidateSource` (S1/S4), `IEditReader` (S2/S3), `IEditClassifier` (S9), `IncidentAssembler` (S10, static).
  Today's implementations are placeholders from P0.8 + `wikidiff` + `classify-edit` v1. Dispute signals wired: removal reason
  (S5 lexicon ported as `RevertReasons`; `Fixtures/s5-parity.jsonl` + `s5_parity.py` keep it identical to the Python) and
  re-insertion (S1 identity restores). Not yet: edit war (S4), dispute templates, source change (S8), kept-in-latest.
- Edits the evidence standard excludes without an assessment are never sent to the LLM. Limits: `Investigations:Pipeline` options.
- Stage 1 = R1 (#8): vector hits in every language, en/sv folded onto their fi sibling by `wikidata_id`; only fi articles come out.
- Caches (#40, SQLite): `EditReadingCache` (span + diff per removed edit, keyed by revision ids + reader version) and
  `InvestigationRuns` (a whole clean run per topic, keyed by `PipelineFingerprint` = versions + classify prompt + model + limits).
  The app's runner is `CachingInvestigationRunner`; `refresh: true` (the page's Re-run) bypasses it. Runs with a degraded
  candidate (LLM down/over budget) are never cached. Bump `InvestigationPipeline.Version` / `CorpusEditReader.Version` when
  their output changes. Score the pipeline: `research/eval/run pipeline --name p1-app -- scripts/investigate.sh variant`.
- Tests: `PipelineKit` = the real stages over fakes (`FakeInvestigationCorpus`, `FakeRevisionStore`, `FakeAnalysisModel`, `FakeQueryEmbedder`).

## LLM analysis (Gemini, `Features/Analysis`, issue #16)

- **Every product LLM call** goes through `IAnalysisModel.RunAsync<T>(new AnalysisRequest("<prompt-id>", vars) { Scope = investigationId })`.
  It never throws for model-side problems — check `result.Outcome` (`Ok | Blocked | Invalid | Truncated | Failed | BudgetExceeded`)
  and degrade that one item. It throws only for programmer errors (unknown prompt, missing variable) and cancellation.
- Prompts are files: `Features/<X>/Prompts/<id>.md` (front matter `id, version, job, temperature, max_output_tokens, thinking_level`,
  then `<<<system>>>` / `<<<user>>>`) + `<id>.schema.json` (JSON Schema → Gemini structured output, re-validated in code).
  Embedded automatically. `{{name}}` = verbatim, `{{data:name}}` = untrusted text in an escaped `<data>` block — use it for anything
  from Wikipedia. Output records are PascalCase C# ↔ snake_case JSON via `AnalysisJson.Options`; keep a schema↔record sync test.
- Model per job (`Triage, Classify, Translate, QueryExpand, Summarize, Judge`) in `appsettings.json` `Gemini:Models` — swapping tiers is config.
  Key: `dotnet user-secrets set "Gemini:ApiKey" "<key>" --project src/AmpersandOfTruth.Web` (or env `Gemini__ApiKey`). The app never reads `~/.gemini/.env`.
- Response cache (SQLite `AnalysisCache`, key = prompt id + version + content hash + model + schema + rendered input) makes reruns free;
  ledger `AnalysisCalls` + spend caps `Gemini:DailyCallCap / DailyCostCapUsd / PerScopeCallCap`. `/analysis` shows usage (playground in Development only).
- Tests of LLM consumers: `tests/AmpersandOfTruth.Tests/Infrastructure/FakeAnalysisModel.cs` (`.Returns("prompt-id", json)`), no HTTP.
- Gotchas: Gemini 4 models reject `thinking_level: minimal` (400); Gemini 4 bills ~300–600 more input tokens per call than 3.x for the same prompt;
  Argon can take 30+ s; a truncated reply is `status: incomplete` with **no** `steps`; safety blocks are HTTP 400 `error.code = safety`.

## Eval contract (P1 experiments, epic #3)

- **`research/eval/CONTRACT.md` is binding for every P1 experiment**: variant I/O (one JSON request on stdin → one JSON response on
  stdout, logs on stderr), the golden-set file, judge/review files, metric definitions. Field names live in `research/eval/schemas/`.
- An incident is matched on its **inserting rev ids** only; `tier` ids are the `EvidenceTiers` ids. Required incident fields
  (`page_id, inserting_rev_ids, removing_rev_ids, tier, score`) are frozen; the rest of `incident.schema.json` is the #37 draft.
  Known `signals[].kind` ids = the `examples` of `kind` in that schema (an open set; the first ten are `TierReasonKind`). New id → add it there.
- Experiments: folder `research/<issue>-<slug>/`, scratch tables `research.<issue>_*`, corpus access from env
  (`CORPUS_HOST/PORT/USER/PW/DB`). The test split is sealed (`EVAL_ALLOW_TEST=1`, decision issues only).
- Changing a frozen shape = schema + example + CONTRACT.md in one commit; `research/eval/tests` must pass (not part of `verify.sh`).
- Score with `research/eval/run` (CONTRACT.md §6): paste its stdout on the experiment's issue, and commit
  `<name>.dev.{scorecard.md,scorecard.json,unlabelled.jsonl,responses.jsonl}` to `research/<issue>-<slug>/results/`
  (the `.log` is git-ignored). After the E3 judge has run, use `run replay … --judgements` instead of re-running the variant.

## Testing

- DB tests: `using var db = new TestDb();` gives a real in-memory SQLite DB with migrations applied. `db.Factory` for services, `db.AddTo(Services)` for bUnit.
  Every context opens its own connection, as in the app, so code that queries from parallel tasks is safe (#106: never share one `SqliteConnection` between contexts).
- bUnit 2.x API: test class inherits `BunitContext`; use `Render<T>()`, `Services.Add...`, `cut.Find(...)`, `.Change()`, `.Click()`, `.Submit()`.
- Async data loading → use `cut.WaitForElement(...)` / `cut.WaitForAssertion(...)`, not immediate `Find`.
- Every new page: add its route to `AppSmokeTests` `InlineData` — this catches DI and routing breakage cheaply.
- Every new service with logic: a few xUnit facts. Don't chase coverage; test what would embarrass us in the demo.
- Time-dependent logic: `Microsoft.Extensions.TimeProvider.Testing` (`FakeTimeProvider`) is available in the test project.

## Agent workflow rules

1. Before finishing any task: `scripts/verify.sh` must pass. If you touched routing/DI/layout, also run `scripts/smoke.sh`.
2. Keep diffs scoped to the task. No drive-by refactors of other features.
3. Never `git push --force`, never rewrite `main` history. Commit in small, working increments.
4. For parallel work, use a git worktree per agent/feature branch; merge to `main` frequently (hours, not days).
5. If you add a dependency, a convention, or a gotcha, update this file in the same commit.
6. Don't leave `dotnet watch` / `dotnet run` processes running when you finish.

## Gemini usage: anything goes

We have a **Tier 3 Gemini API key, paid for by Google** — its rate limits are far above anything we can hit and cost is
not our concern. So: **no limits on Gemini usage in this project.** Run as many workers / sessions / batch jobs
concurrently as is useful, use the strongest models, rerun and re-sample freely, and never trim scope, prompts or
eval runs to save calls or tokens. Ignore any older note that says otherwise. The app's `Gemini:DailyCallCap /
DailyCostCapUsd / PerScopeCallCap` are only runaway-loop tripwires — raise them in `appsettings.json` whenever they get in the way.

## Gemini workers

Claude orchestrates, Gemini implements. Full workflow: `.claude/skills/gemini/SKILL.md` (`/gemini`).
`scripts/gemini/run.sh <id>` runs Gemini headless on `.tasks/<id>/spec.md` in an isolated worktree
(`../AmpersandOfTruth.worktrees/<id>`, branch `gemini/<id>`, macOS sandbox: writes confined to the worktree),
then independently runs `verify.sh`. `land.sh <id> "<msg>"` rebases + re-verifies + squash-merges; `discard.sh`, `status.sh`.
Worker-only rules are in `GEMINI.md`. API key: `~/.gemini/.env` (outside the repo) — never in the repo.
**Known limitation:** inside the macOS seatbelt sandbox `dotnet` can't start (CoreCLR needs `sysctl` reads the profile denies), so
workers write code without compiling; `run.sh`'s own `verify.sh` (outside the sandbox) is the real check — review its log, and expect
a feedback round for compile errors. Workers also can't run `dotnet ef`/`dotnet sln` (they may hand-write the output — re-generate to confirm).

## Gotchas

- `--all-interactive` is set: `<Routes @rendermode="InteractiveServer" />` in `App.razor`, so pages need no `@rendermode` of their own.
- Pages are prerendered once on the server, then rendered again when the circuit connects → `OnInitialized` runs twice. Don't do side effects there.
- `EditForm` needs a `FormName` (static SSR requirement even in interactive apps).
- Disconnected circuit = lost in-memory scoped state. Fine for a demo; persist anything that matters.
- Projects were renamed from the placeholder `Junction.Web`/`Junction.Tests` (`SomeMysteriousAppForJunction.sln`). Older branches:
  rebase onto `main` (git follows the folder rename) and fix `namespace Junction.Web…` → `AmpersandOfTruth.Web…` in new files.
  `UserSecretsId` is unchanged, so user-secrets still apply; a leftover `src/Junction.Web/app.db` can just be deleted.
- Wikitext diffs: one engine, `WikitextDiff.Compare(parentText, revText)` (`Features/WikiDiff`, static, thread-safe, no DI);
  experiments call `scripts/wikidiff.sh batch` with many pairs per call, never a Python re-implementation. Changing its
  output → regenerate `research/29-wikidiff/expected.jsonl` (an xUnit test guards it) and update CONTRACT.md §9.
