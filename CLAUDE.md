# SomeMysteriousAppForJunction

48-hour Junction hackathon project. **Speed > polish, but `main` must always demo.**
Blazor Web App on .NET 10, **Interactive Server** render mode everywhere (no WASM, no separate API).
Persistence: **EF Core 10 + SQLite** (`src/Junction.Web/app.db`, git-ignored, migrated automatically on startup).

## Commands

| What | Command |
|---|---|
| Green gate (build + missing-migration check + all tests) — run before saying "done" | `scripts/verify.sh` |
| Boot real app + curl routes | `scripts/smoke.sh [/route ...]` |
| Hot-reload dev server → http://localhost:5172 | `scripts/dev.sh` (run in background; it never exits) |
| Single test class | `dotnet test --filter "FullyQualifiedName~NotesPageTests"` |
| Add NuGet package | `dotnet add src/Junction.Web package <Name> --version 10.*` (latest is 11.x = .NET 11, won't install) |
| Add EF migration | `dotnet ef migrations add <Name> --project src/Junction.Web --output-dir Data/Migrations` |
| Reset local DB | `rm src/Junction.Web/app.db` (recreated on next start) |

## Layout

```
src/Junction.Web/
  Program.cs                  # one `builder.Services.AddXFeature()` line per feature — nothing else feature-specific
  _Imports.razor              # global usings for ALL .razor files (lives at root on purpose)
  Data/
    AppDbContext.cs           # the single DbContext — features don't edit it (see Persistence)
    DataFeature.cs            # AddAppData() + MigrateDatabaseAsync()
    Migrations/               # generated by dotnet ef — never hand-edit the snapshot
  Components/
    App.razor, Routes.razor   # shell; rarely touched
    Layout/                   # MainLayout, NavMenu (add nav links above the marker comment)
    Pages/                    # Home, Error, NotFound only
    Shared/                   # reusable UI bits (EmptyState, …) — used by 2+ features
  Features/<Feature>/         # ⭐ all real work goes here — vertical slices
    <Feature>Page.razor       # @page route(s)
    <Feature>Feature.cs       # AddXFeature(IServiceCollection) extension — DI registrations
    <Entity>Configuration.cs  # IEntityTypeConfiguration<T> — table, keys, indexes
    *.cs                      # models (records), services/stores
tests/Junction.Tests/
  Infrastructure/             # TestDb (in-memory SQLite + real migrations), AppFactory (app on temp DB)
  Features/<Feature>/         # mirrors src: service unit tests + bUnit component tests
  Smoke/AppSmokeTests.cs      # boots the real app via WebApplicationFactory; add new routes to the InlineData list
```

`Features/Notes` is the **reference slice** — copy its shape. Delete it once real features exist (remove its `AddNotesFeature()` line, nav link, tests, smoke route).

## Conventions

- **One feature = one folder.** Parallel agents should only collide on `Program.cs` (one line) and `NavMenu.razor` (one block). Keep it that way.
- Namespaces follow folders (`Junction.Web.Features.Notes`). File-scoped namespaces, primary constructors, records for data.
- Services: interface only if there are 2+ implementations or you need to fake an external API. Otherwise inject the concrete class.
- Singleton state is shared by **every user/circuit** → must be thread-safe. Per-user state → `AddScoped` (scope = one browser tab's circuit).
- When a service raises events consumed by components, update UI via `InvokeAsync(StateHasChanged)` and unsubscribe in `Dispose`.
- Inject `TimeProvider` instead of `DateTime.Now` (testable).
- UI: Bootstrap 5 classes are already loaded (`wwwroot/lib/bootstrap`). Don't add a component library unless the team decides to.
- Put `data-testid="..."` on elements tests interact with; tests select by it, not by CSS classes.
- Secrets (API keys): `dotnet user-secrets set "Key" "value" --project src/Junction.Web`, read via `IConfiguration`. Never commit keys; never put them in `appsettings*.json`.

## Persistence (EF Core + SQLite)

- **Don't add `DbSet` properties to `AppDbContext`.** Add an `IEntityTypeConfiguration<T>` in the feature folder (auto-discovered) and query with `db.Set<T>()`.
- Services inject `IDbContextFactory<AppDbContext>` and create a context **per operation** (`await using var db = await dbFactory.CreateDbContextAsync()`). Never inject `AppDbContext` into components or keep one in a field — a Blazor circuit lives for the whole tab session and DbContext isn't thread-safe.
- Read queries: `.AsNoTracking()`. Bulk delete/update: `ExecuteDeleteAsync` / `ExecuteUpdateAsync`.
- Changed an entity or configuration → add a migration in the same commit. `verify.sh` fails if you forget.
- SQLite limits: `DateTimeOffset` is auto-stored as UTC ticks (a convention in `AppDbContext`) so it sorts — always use UTC. `decimal` can't be ORDER BY'd or SUM'd in SQL → use `double` or long cents for money/scores.
- **Parallel branches + migrations:** both branches edit `AppDbContextModelSnapshot.cs` → merge conflict. Fix: take `main`'s snapshot, delete *your* migration files, re-run `dotnet ef migrations add`. Never hand-merge the snapshot.
- Seed demo data inside a feature service, idempotently (check `AnyAsync()` first), not in migrations.

## Testing

- DB tests: `using var db = new TestDb();` gives a real in-memory SQLite DB with migrations applied. `db.Factory` for services, `db.AddTo(Services)` for bUnit.
- bUnit 2.x API: test class inherits `BunitContext`; use `Render<T>()`, `Services.Add...`, `cut.Find(...)`, `.Change()`, `.Click()`, `.Submit()`.
- Async data loading → use `cut.WaitForElement(...)` / `cut.WaitForAssertion(...)`, not immediate `Find`.
- Every new page: add its route to `AppSmokeTests` `InlineData` — this catches DI and routing breakage cheaply.
- Every new service with logic: a few xUnit facts. Don't chase coverage; test what would embarrass us in the demo.

## Agent workflow rules

1. Before finishing any task: `scripts/verify.sh` must pass. If you touched routing/DI/layout, also run `scripts/smoke.sh`.
2. Keep diffs scoped to the task. No drive-by refactors of other features.
3. Never `git push --force`, never rewrite `main` history. Commit in small, working increments.
4. For parallel work, use a git worktree per agent/feature branch; merge to `main` frequently (hours, not days).
5. If you add a dependency, a convention, or a gotcha, update this file in the same commit.
6. Don't leave `dotnet watch` / `dotnet run` processes running when you finish.

## Gotchas

- `--all-interactive` is set: `<Routes @rendermode="InteractiveServer" />` in `App.razor`, so pages need no `@rendermode` of their own.
- Pages are prerendered once on the server, then rendered again when the circuit connects → `OnInitialized` runs twice. Don't do side effects there.
- `EditForm` needs a `FormName` (static SSR requirement even in interactive apps).
- Disconnected circuit = lost in-memory scoped state. Fine for a demo; persist anything that matters.
